# 대응 타임라인·체크리스트 (오케스트레이터)

장애 대응 전체의 시한·진행상황을 추적하는 상태 대시보드. 다른 4개 스킬이 만드는 산출물의 마감과 완료 여부를 한 화면에 모은다.

## 경계
- **현황 표시까지만.** 실제 보고·발송·제출은 사람이 한다.

## 입력
- `incident.json`. 시한 계산: `detection.detected_at`(+24h), `orders[].claim_received_at`(+14영업일). 상태: `reporting{}`의 각 항목 status.

## 실행
```bash
python3 scripts/incident_tracker.py <incident.json> [--now <ISO>] [--out <경로>] [--stdout-only]
```
- `--now`: 기준 현재시각(미지정 시 실제 현재).
- 호출할 때마다 그 시점 기준으로 D-counter를 재계산한다. (상태 없는 stateless — 사실은 incident.json에서 읽음)
- 출력은 항상 `<incident 폴더>/out/<id>_대응타임라인.md`로 자동 저장된다(`--out`으로 경로 변경, `--stdout-only`로 저장 생략). 문서 상단에 생성 기준시각이 박힌다. 모델은 실행 후 저장된 파일 경로를 사용자에게 보고하라.
- 읽기 전용 대시보드이므로 별도의 AskUserQuestion 인테이크는 필요 없다.

## 출력
- 보고/산출물별: 상태 아이콘(✅제출완료/📝초안/⬜미생성/➖해당없음) · 시한 · 남은시간 · 담당 스킬 · 조건.
- 시한 임박(6시간 내) 🔴 / 24시간 내 🟠 강조.
- **'지금 가장 급한 것'**: 미완료 항목 중 가장 임박한 마감과 실행할 스킬을 지목.
- **병행 신고 자동 추가(금감원 보고로 갈음 안 됨)**: `classification.incident_category=="침해사고"`면 **정보통신망법 §48조의3 침해신고(KISA/과기정통부, 인지+24h)** 행을, `security.personal_data_affected`면 **개인정보 유출신고(인지+72h)** 행을 시한과 함께 자동 추가한다.

## 상태 갱신 (정확도의 핵심)
- 상태는 `incident.json`의 `reporting{}`에서 읽는다. 각 스킬(1·2·3·5)을 실행해 산출물을 만들면 해당 키의 status를 `초안`/`제출완료`로 갱신해야 대시보드가 정확하다.
- 예: 금감원 최초보고서를 만들면 `reporting.fss_initial.status = "초안"`, EFARS 제출 후 `"제출완료"` + `submitted_at` 기록.
- 모델은 사용자에게 "방금 만든 산출물 상태를 갱신할까요?"를 물어 incident.json을 업데이트할 수 있다.

## 이사회 보고 조건
- `board_report` 항목은 스킬5(exec-board-report)의 중대성 판정에 따라 '해당없음/대상'이 갈린다. 정확히 하려면 스킬5를 `--json`으로 먼저 돌려 판정을 반영.

## 데이터 모델
추적 항목이 늘면 `shared/incident.schema.json`의 `reporting{}`과 스크립트의 items 목록을 함께 갱신.

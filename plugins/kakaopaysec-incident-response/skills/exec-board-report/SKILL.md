# 경영진·이사회 상황보고서 생성기

장애를 경영진·이사회에 보고하는 산출물을 만든다. 근거: 전자금융감독규정(CISO→CEO 보고 / 안전성·신뢰성 중대영향 사항 이사회 보고, 2025.8.5 시행) + 지배구조법 내부통제.

## 경계
- **보고서 생성까지만.** 실제 보고·심의는 사람이 한다.
- 이사회 보고대상 판정은 **'권고'**다. 최종 판단은 CISO/이사회.

## 입력
- `incident.json`. 특히 `classification.incident_category`, `security.personal_data_affected`, `impact.affected_users_count`/`disruption_minutes`/`incident_amount_krw`, `cause.external_factor`/`affected_other_firms`.
- **자동 사전 검증**: 스크립트 실행 시 enum·필수필드를 자동 점검하고 오류 시 중단(`--no-validate`로 우회). `run_all_skills.py`도 맨 앞에서 1회 검증.

## 실행
```bash
python3 scripts/generate_management_report.py <incident.json> [--tier auto|a|b|both] [--json] [--out PATH] [--stdout-only] [--now ISO]
```
- `auto`(기본): 경영진 속보(Tier A) 항상 + 중대 판정 시 이사회 보고서(Tier B).
- `--json`: 이사회 보고대상 판정 결과만 출력(타임라인 스킬 연동용). JSON 모드는 파일 저장 안 함.
- 출력은 항상 `<incident 폴더>/out/<id>_경영진이사회보고.md`로 자동 저장된다(경로는 `--out`으로 덮어쓰기, `--stdout-only`/`--json`이면 저장 생략). 저장 경로를 사용자에게 보고하라.

## 중대성 판정 규칙 (스크립트 자동, 권고)
- **필수 사유**(있으면 이사회 보고대상): 침해사고 / 개인정보·신용정보 영향.
- **가중 요인**(2개 이상이면 대상): 영향 이용자수 ≥ 10만 / 중단 ≥ 60분 / 사고금액 ≥ 1억 / 외부 제3자+타사 동시영향.
- 임계치는 회사 정책에 맞게 스크립트 상단 상수에서 조정 가능.

## 보고서 필수 요소 (규정 반영)
- Tier A(경영진 속보): 개요·발생/인지시각·영향·원인·대응현황·규제보고 상태·**병행 신고 시한(침해사고→정보통신망법 KISA 24h / 개인정보→72h, 금감원 보고로 갈음 안 됨)**·이사회 보고대상 여부·다음 보고.
- Tier B(이사회): 중대성 판단·사고개요·침해/개인정보 영향·외부 제3자 리스크·재무/평판 영향·재발방지·거버넌스(책무구조도 책임임원·정보보호위 심의).

## AskUserQuestion 인테이크 (incident.json 없을 때, 필수)
자유서술로 묻지 말고 **AskUserQuestion으로 한 문항씩** 받는다(regulator-incident-report와 동일 규율).

**⛔ 철칙 — 추측 금지**: 이사회 판정을 가르는 값을 **임의로 추정하지 않는다.** 모르면 각 문항의 **'파악 중/미상'** 을 고르게 하고 incident.json에 **null**로 둔다. **구간 중앙값으로 법정/정책 임계(이용자 10만·중단 60분·사고금액 1억)를 넘겨짚지 말 것** — 임계 부근이면 정확값 또는 "임계 이상/미만 확실"을 물어라.

**필수 문항 (이사회 '필수사유' 판정 입력값 — 반드시 물어라)**
1. **사고 유형 대분류** (header: `사고유형`) — 전산장애 / 침해사고 / 전자금융사기 / 파악 중  ← `필수사유`(침해사고면 즉시 이사회 대상) 판정에 직결
2. **개인정보·신용정보 유출 동반** (header: `개인정보`) — 없음 / 개인정보 / 신용정보 포함 / 둘 다 / 파악 중  ← `필수사유`(개인정보 영향이면 즉시 이사회 대상) 판정에 직결
3. **영향 이용자수** (header: `영향규모`) — 정확한 수 직접 입력(권장) / 10만명 이상 확실 / 10만명 미만 확실 / 미상
4. **지연·중단 시간** (header: `중단시간`) — 정확한 분(권장) / 60분 이상 확실 / 60분 미만 / 미상

(후속) 외부요인·타사 동시영향, 사고금액은 가중요인 판정에 필요하면 추가 문항으로. regulator-incident-report로 만든 incident.json이 있으면 **그대로 재사용**(중복 질문 금지).

## 모델 역할
- 판정 결과와 사유를 사용자에게 먼저 설명(왜 이사회까지/왜 경영진 선에서). **필수사유(사고유형·개인정보)가 미상이면 추측하지 말고 반드시 확인 후 판정**한다.
- 보고서의 '(기재 필요)' 슬롯(책임임원·정보보호위 심의일·평판영향)을 사용자에게 물어 채운다.
- 임계치가 회사 기준과 다르면 조정 제안.

## 데이터 모델
새 판정 입력(예: 심각도 등급 필드)이 필요하면 `shared/incident.schema.json`과 스크립트를 함께 갱신.

## 1. 라우팅 정확도 (핵심 지표) — 22/22
독립 서브에이전트에게 6개 스킬 description + 22개 쿼리를 주고 각 쿼리를 라우팅하게 함(커맨드/Skill 툴 아티팩트 배제, 순수 description 판단).
- positive 18개(스킬별 3개) → **전부 올바른 스킬**로 라우팅
- 무관 4개(리액트·파이썬·매출대시보드·회의록) → **전부 none**
- 교차 혼동(예: 보상 요청이 금감원 스킬로) **0건**
→ description이 서로 명확히 구분되고 의도대로 라우팅됨.

## 2. run_eval 결과와 해석
run_eval(skill-creator)로 6스킬 × 7쿼리 × 2회를 2차례(개선 전/후) 실행:
- 모든 스킬 positive 발동률 ≈ 0~17%, negative 오발동 0%.
- 개선 전후 사실상 동일(명백히 온토픽인 "금감원 사고보고서 만들어줘"도 0%).

**해석 = 하니스 아티팩트, description 문제 아님.**
- run_eval는 스킬을 `.claude/commands/`에 슬래시 커맨드로 등록하고 `Skill` 툴 호출 여부로 트리거를 감지한다.
- 이 환경의 헤드리스 `claude -p`는 자연어 프롬프트에 대해 커맨드/Skill 툴을 부르지 않고 **직접 답을 생성**한다(수동 프로브가 2분간 실제 보고서를 작성하다 타임아웃된 것과 일치).
- 따라서 positive가 일률적으로 0%, negative만 완벽 → 실제 트리거 경로를 측정하지 못함.
- 반면 §1 라우팅 테스트는 실제로 중요한 질문(설명만으로 올바른 스킬 선택)을 직접 측정 → 100%.

## 3. 결론
- **기능·라우팅 모두 검증 완료.** 안전성(무관 프롬프트 미발동)도 견고.
- run_eval 수치는 이 환경에서 대표성이 없으므로 판단 근거로 쓰지 않음.
- description은 개선판(액션·키워드 front-load, pushy) 유지.

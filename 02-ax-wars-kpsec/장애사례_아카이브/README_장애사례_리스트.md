## 0. 요약 — "전산장애 42건"의 정체

언론·국정감사에서 인용되는 **카카오페이증권 42건**은 개별 문서화된 42개 사건이 아니라, **금융감독원 제출 기준 MTS 전산장애 연간 집계의 누적치**(2022.1~2026.3)다.

| 연도 | 카카오페이증권 MTS 전산장애 | 비고 |
|---|:---:|---|
| 2022 | 4건 | 국내주식 매매 정식 출시(2022.4) 원년 |
| 2023 | 9건 | 해외주식(미국) 본격화(2023.7) |
| 2024 | 11건 | 블루오션 ATS 사태(8월) 포함 |
| 2025 | 13건 | 10월에만 4회 '먹통' |
| 2026 (1~3월) | 5건 | 조사대상 12개사 중 **단독 최다** |
| **누계** | **42건** | 4+9+11+13+5 = 42 |

- **출처**: 국회 정무위 이양수 의원실이 500만 계좌 이상 증권사 12곳에서 제출받은 자료(2026.4). 굿모닝경제·파이낸셜포스트·이투데이 보도.
- 같은 자료에서 **토스증권도 42건**으로 공동 최다. 두 핀테크사 합산 84건이 12개사 전체 190건의 **약 44%**.
- 카카오페이증권은 12개사 중 **유일하게 4년 연속 장애 건수 증가**(4→9→11→13).
- **주의(별개 통계와 혼동 금지)**: ▲2025 국감 "증권업 5년 497건·267억"(추경호 의원실) ▲2026.2 "9개사 168건·배상 53억"(이헌승 의원실) 은 기준·기간이 다른 별도 집계. ▲카카오**페이**(결제법인) 과징금 129.76억(2026.1)·59.68억(2025.1)은 **개인정보 무단제공** 사건으로 증권 전산장애와 무관.
- **금감원 대응**: 2026.4.14 카카오페이증권 **IT부문 현장점검** 착수("거래량 급증 대비·MTS 오류" 집중). 확정 제재는 현재까지 공개 확인 안 됨.

> 42건 중 **개별 날짜·상세가 언론에 공개된 사건은 아래 8건**. 나머지(2022년 4건, 2023년 7건, 2024년 10건 등)는 연간 집계로만 존재해 개별 재구성이 불가(미상)하다.

## 4. 데이터 한계 및 유의

1. **개별 사건의 이용자수·미체결 규모·손실 금액은 거의 전부 언론 비공개** → `affected_users_count`, `incident_amount_krw`는 대부분 `null(미상)`. 최초 대응 시점에도 실제로 규모는 미확정인 경우가 많다.
2. **발생·지속 시각은 보도 기반 추정**([추정] 표기). 정밀 시각은 EFARS 제출 시 내부 APM 로그로 대체해야 함.
3. **보상 실지급액은 확인된 출처 없음**. 회사 상시 보상정책: `보상금=(보상기준가−실제체결가)×수량`, 단 미체결 매도주문·해외 현지 귀책은 제외.
4. 규정/법령 판정은 **2026년 현행 기준**으로 통일(사건 당시 기준과 다를 수 있음 — 사용자 지시).

## 5. 이 아카이브 재생성 방법

각 사건 폴더의 `incident.json`을 입력으로 5개 스킬을 일괄 실행:

```bash
# 단일 사건
python3 kakaopaysec-incident-response/shared/scripts/run_all_skills.py <사건폴더>/incident.json

# 전체 재생성
cd 장애사례_아카이브 && for d in */; do \
  python3 ../kakaopaysec-incident-response/shared/scripts/run_all_skills.py "$d/incident.json"; done
```

- 기준시각(--now)은 미지정 시 **인지시각+5분**(최초 대응 시점)으로 자동 설정.
- 산출물은 각 사건 `out/`에 `.md`로 자동 저장. PII 미동반 사건은 유출신고서 파일을 생략(판정만 수행).

## 2. 시나리오 매트릭스 검증 결과 (14종)

각 시나리오의 incident를 만들어 **판정 로직을 직접 호출**(fss 트리거·이사회 중대성·유출 신고의무)하고, 고객공지는 실제 실행해 모드를 확인. 기대값과 100% 일치.

| S13 | 신용정보(계좌·거래내역)·둘 다 | 대상 | 대상 | **대상** | realtime | ✅ |
| S14 | 전산장애+개인정보 동반(복합) | 대상 | 대상 | 대상 | realtime | ✅ |

**핵심 확인 포인트**
- **경계 판정 정확**: 시간 단독(35분↑=대상, 5분=비대상), 규모 결합(15분+1.2만명=대상), 제외사유(1개영업점·공개웹=제외).
- **1만명 룰 독립 작동**(S02): 30분 미만이라도 10분↑+1만명↑이면 대상.
- **유출 신고 3근거 분리**(S07 1호=1천명 / S08 2호=민감·고유식별 규모무관 / S09 외부침해지만 유출없음→해당없음).
- **사기 일괄보고**: 3억 미만(S11·S12)만 익월 일괄보고 안내, 5억(S10)은 미안내.
- **이사회 필수사유 vs 가중요인**: 개인정보·침해 동반이면 필수사유로 즉시 대상(S07·S14), 순수 장애는 가중요인 2개↑라야 대상(S04만).
- **복구 상태 연동**: 복구완료(S01)만 recovery 공지, 진행중은 realtime — '정상화' 오공지 방지.

> 판정 로직 커버리지: **현행 법령상 구분되는 모든 케이스 = 14/14 정확**.

## 3. 산출물 커버리지 — 커버 / 경계 / gap

판정은 100%이나, **산출물(담당자가 만들어야 할 문서)** 관점에서 스킬이 닿는 범위와 경계를 구분한다.

### ✅ 완전 커버 (스킬 산출물 존재)
- 전산장애(전 유형) → 금감원 보고·고객공지·경영진/이사회·타임라인
- 개인정보/신용정보 유출(침해 동반) → 유출 통지문·감독기관 신고서(72h)
- 이사회 보고 필요 중대사고 → 이사회 보고서(Tier B)

### ⚠️ 경계 / 부분 커버 (판정은 되나 전용 산출물 없음)
- **전자금융사기사고(보이스피싱 등)**: fss가 보고 대상/제외/일괄보고까지 판정하나, **사기 피해자 통지·구제 전용 산출물 없음**. → 아래 §4에서 법령상 gap인지 범위 밖인지 검증.
- **순수 침해사고(개인정보 유출 없는 DDoS·해킹)**: fss 보고+경영진/이사회는 되나, **정보통신망법상 KISA 침해사고 신고 산출물 없음**. → §4 검증.

### ✅ 후속 개선 — 완료 (테스트 후 반영)
- 별지 제2호서식 **원본 PDF 대조 → `reference/efars-rules.md` 보완**: 표지(공문)·별첨1 3분류 체크박스·공격자 정보·별첨2(일괄보고)·incident↔서식 매핑표 추가.
- **incident.json → 공식 서식 PDF 생성기**(`generate_fss_pdf.py`) 추가: ①표지(공문) + ②별첨1(사고내용) 원본 포맷 재현, **표지에 정식 법인명 「카카오페이증권 주식회사   대표이사   (인)」** 반영, 헤드리스 브라우저로 HTML→PDF. 아카이브 8건 전체 PDF 생성 완료.

## 4. 법령 정밀 검증 (독립 감사 — 법제처 원문·로펌 해설 교차확인, 2026 현행)

| # | 검증 대상 | 결론 | 요지 |
|---|---|---|---|
| 1 | 시행세칙 제7조의4 (30분 / 10분+1만명 / 24h·2월·6월 / 사기 100만↓·3억↓) | **✅ 현행 유효** | 30분·10분+1만명은 2023년 개정 신설 최신 기준. 수치·시한 모두 일치 |
| 2 | 개인정보보호법 §34·시행령 §40 (1천명/민감·고유식별/외부침해, 72h KISA·보호위) | **✅ 현행 유효** | 2024.3 시행 PIPA 반영과 일치 |
| 3 | 정보통신망법 §48조의3 침해사고 신고(KISA·과기정통부) | **🔴 gap 맞음(조건부)** | 순수 해킹·DDoS(개인정보 유출 없음)도 신고 의무 성립 가능. **금감원 보고로 자동 갈음 안 됨.** 2026.3 개정으로 **인지 후 24시간 이내** 명문화 |
| 4 | 전기통신금융사기(보이스피싱) 피해자 통지·환급 | **범위밖(인접 gap)** | 통신사기피해환급법상 지급정지·통지·채권소멸공고는 법정 산출물이나 '전자금융사기사고'(해킹형)와 개념 다름 → 범위밖. 단 **해킹發 무권한 전자금융거래 배상·통지(전자금융거래법 §9)**는 인접 gap |
| 5 | 기타 | 대부분 커버/범위밖 | 신용정보법 §39조의4(1만명↑ 금융위·금감원 신고)는 privacy-breach가 '병행 안내'로 부분 커버 — **이원 신고 트리거 명시화 권장**. 재해복구전환(BCP 발동) 통보는 exec-board-report 체크항목化 여지 |

### 4-1. 확인된 개선 권고 (우선순위)
- **[P1·실제 gap → ✅ 구현 완료] 정보통신망법 침해사고 신고 판정 분기 추가**: 침해사고(`incident_category=="침해사고"`)일 때 개인정보 유출 여부와 **무관하게** KISA/과기정통부 24시간 신고 대상 가능성을 띄운다.
  - **regulator-incident-report**: 「1-1. 병행 신고 점검」 경고 블록 추가(정보통신망법 §48조의3 24h + 개인정보 동반 시 72h, "금감원 보고로 갈음 안 됨" 명시).
  - **response-deadline-tracker**: 침해사고 시 **KISA 침해신고(인지+24h)** 행, 개인정보 동반 시 **유출신고(인지+72h)** 행 자동 추가 + D-counter.
  - schema/`set_status`에 `kisa_report`·`privacy_report` 상태키 추가(서비스 포섭 여부는 사내 법무 확인 안내 문구 병기).
- **[P2 → ✅ 구현 완료] 신용정보법 이원 신고 명시화**: privacy-breach가 신용정보 1만명↑ 시 **신용정보법 §39조의4 금융위·금감원 신고를 개인정보위(72h)와 분리 트랙**으로 명시 + 침해사고면 KISA 24h 교차참조. exec-board-report Tier A/이사회 보고서에도 병행 신고 시한 반영.
- **[P3·문구] fss 중간·종결보고 주기 표현**을 "**종결 시까지 매 6월**"로 정확화(현재도 의미상 동일하나 표현 점검) — 미반영(경미).
- **[P4] 무권한 전자금융거래(전자금융거래법 §9) 배상·통지** 트랙: 침해사고로 이용자 금전피해 시 별도 통지 — 현재 플러그인 부재(인접 gap, 범위 확장 시 검토) — 미반영(범위밖).

### 4-1-a. 스킬 간 정합성 보강 (2026-07-02, 완료)
regulator-incident-report 인테이크 개편(사고유형 최상위 분기·추측 금지)에 맞춰 뒷단 스킬 일관성 보강:
- **exec-board-report**: 인테이크에 **사고유형·개인정보 유출 필수 문항**(이사회 필수사유 입력값, 추측 금지) 명시 + Tier A/B에 **병행 신고(KISA 24h·개인정보 72h·신용정보법)** 반영.
- **customer-outage-notice·exec-board-report**: **"추측 금지/미상" 철칙** 문구 통일. customer-outage-notice에 "PII 정보주체 통지는 privacy-breach 담당" 교차참조.
- **form_mapping 단일 원천 확장**: exec-board-report·response-deadline-tracker가 `form_mapping.selected_category`를 사용(사고유형 정규목록 전 스킬 단일화).
- **공통 사전 검증**: `shared/scripts/validate_incident.py` 신설(enum·필수필드), `run_all_skills.py` 맨 앞 자동 실행 → 잘못된 incident.json을 어느 스킬 실행 전에 차단. pytest 5건 추가(총 25건).

> 위 권고는 **테스트 결과 도출된 개선안**이며, 규제 대응 확정 전 사내 법무·감독당국 확인 권장(에이전트 감사 의견).

### 4-2. 최종 판정
- **판정 로직 커버리지**: 현행 법령상 구분되는 14/14 케이스 **정확** (금감원·이사회·유출신고·고객공지).
- **산출물 커버리지**: 전산장애·개인정보/신용정보 유출·이사회 보고 = **완전 커버**. **실제 gap이던 순수 침해사고 정보통신망법 KISA 신고(P1)는 fss 경고 블록 + tracker 24h 시한으로 보강 완료.**
- 결론: **"모든 장애에 적절히 대응"은 판정 기준 충족 + 병행 신고(정보통신망법·개인정보보호법) 분기까지 보강되어 산출물 기준으로도 사실상 완비.** (P4 무권한거래 배상·통지 트랙만 향후 범위 확장 시 검토)

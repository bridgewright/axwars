# 카카오페이증권 전산장애 대응 — 전체 워크플로우 (IT 담당자 관점)

> 목적: 장애 발생 시 IT 담당자 관점의 end-to-end 대응 흐름을 정리하고, 그 안에서 **Codex 장애대응 산출물 플러그인이 커버하는 보고**와 **커버하지 못하는 영역**을 구분한다.
> 작성 기준: 전자금융감독규정 시행세칙 제7조의4(정보기술부문 사고보고) + 업계 표준 대응 실무.

---

## 0. 핵심 경계 — EFARS 제출은 사람이 한다

- **EFARS(전자금융사고대응시스템)**: 금융감독원이 운영하는 웹 기반 사고보고 시스템. 회사가 사전 지정한 **「비상연락 담당자」(통상 CISO 조직)** 가 접속해 사고·장애보고서를 등록.
- **공개 API 없음 / 보안격리망** → 플러그인이 EFARS에 자동 제출하는 것은 불가능.
- 따라서 플러그인의 역할 = **"제출 직전 단계의 완성된 산출물(별지 제2호서식에 맞춰 채운 보고서 + 복붙용 필드 블록)"** 생성. 실제 입력·게시·지급은 사람이 실행.

## 1. 전체 워크플로우 (시간순)

`T0` = 장애 발생/인지 시점.

|---|---|---|---|---|---|
| T0 | ① 탐지 | 모니터링/NOC·SRE | APM 알람·고객민원·CS 인입으로 감지 | ❌ | (모니터링 솔루션 영역) |
| +수분 | ② 장애 선언·등급판정 | 상황실장/IT본부 | 심각도 등급 결정, War room 소집 | ✅ | 경영진 속보(1보) — 스킬 5 |
| +수분 | ②-1 경영진 보고 | CISO/IT본부 | CEO·리스크관리에 상황 보고(전자금융감독규정상 CISO→CEO 보고) | ✅ | 경영진 상황보고 — 스킬 5 |
| +수분 | ③ 영향평가 | 운영+인프라 | 영향 서비스·중단시간·영향 이용자수 산정 | ❌ | (플러그인 입력값) |
| +5~15분 | ④ 1차 고객 공지 | CS+IT | 홈페이지·MTS·알림톡에 장애+대체주문수단 게시 | ✅ | 고객 공지문(실시간) |
| 진행중 | ⑤ 유관기관 통보 | 운영/IT | (주문전달 영향 시) 거래소·코스콤 통보 | ⚠️부분 | 통보 메모 초안 |
| 진행중 | ⑥ 복구 작업 | 인프라팀 | DR 전환(Active-Active)·롤백·외부 브로커 재연결 | ❌ | (엔지니어링 실행) |
| ≤24h | ⑦ 금감원 최초보고 | CISO/비상연락 담당자 | EFARS 등록(별지 제2호서식 별첨1) | ✅ | 금감원 사고보고서 초안(최초) |
| 복구시 | ⑧ 복구완료 공지 | CS+IT | 정상화 시각·원인 요약 공지 | ✅ | 고객 공지문(복구) |
| +수일 | ⑨ RCA/포스트모템 | IT+인프라 | 근본원인·타임라인·재발방지 정리 | ✅ | 포스트모템 문서 |
| 2월/6월 | ⑩ 중간·종결보고 | CISO/컴플라 | EFARS 중간·종결(원인·조치·재발방지·배상완료) | ✅ | 금감원 사고보고서 초안(중간/종결) |
| 사후 | ⑪ 보상 접수·산정·통지 | CS+컴플라 | 민원 접수→손해액 산정→14영업일 내 통지 | ✅ | 보상 산정 검토표 |

| 사후 | ⑫ 분쟁조정·재발방지 이행 | 컴플라/IT | 금투협 분쟁조정 대응, 개선과제 추진 | ❌ | (의사결정·변론·실행) |

## 2. 플러그인 커버 경계

### ❌ 커버 불가
- 탐지·모니터링(①) — APM/로그모니터링 솔루션
- 실제 복구·DR 전환(⑥) — 인프라 엔지니어링
- EFARS 실제 제출(⑦⑩ 마지막 클릭) — 보안격리망, 사람이 입력
- 고객 공지 실제 발송(④⑧) — 알림톡/홈페이지 게시 시스템 (단, 문안은 생성)
- 보상 지급 의사결정·자금집행(⑪ 후단) — 컴플라이언스 승인
- 분쟁조정 변론(⑫)

### ✅ 커버 가능 — "사실(타임라인·영향·원인·주문데이터) → 규정양식 산출물" 생성
입력: 장애 타임라인(인지/발생/종료 시각) + 영향범위(서비스·이용자수·중단시간) + 원인(내부/외부 브로커) + 미체결 주문 데이터.

## 3. 산출물 5종 (= 1개 플러그인 = 5개 스킬)

| 산출물 | 대응 단계 | 형태 |
|---|---|---|
| ① 금감원 사고보고서 초안(최초/중간/종결) | ⑦⑩ | 별지 제2호서식 별첨1 미러링 — EFARS 복붙용 필드 블록 + 첨부용 문서 |
| ② 고객 공지문(실시간/복구) | ④⑧ | 채널별 3버전(홈페이지/MTS 상세, 알림톡 압축, 요약 배너) |
| ③ 보상 산정 검토표 | ⑪ | 주문건별 표 + 통상손해 차액 자동계산 + 14영업일 카운트다운 |
| ⑤ 경영진·이사회 상황보고서 | ②②-1⑪-1 | Tier A 경영진 속보(1보/2보) + Tier B 이사회 보고서 + **이사회 보고대상 자동 판정** |
| ④ 대응 타임라인·체크리스트 | 전체 | 규제 시한 D-counter + 단계별 done/pending |

> 근거: 경영진 보고 = 전자금융감독규정(CISO→CEO). 이사회 보고 = 전자금융감독규정 중대영향 사항(2025.8.5 시행) + 지배구조법 내부통제. 법정 정형양식은 없고 회사 내부 양식 + 규정상 필수요소(중대성 판단·침해/개인정보 영향·제3자 리스크·재발방지)를 채움.

## 4. 한 장 요약

```
[탐지·복구·EFARS제출·발송·지급] = 사람/시스템 (플러그인 밖)
                 │  사실 입력(타임라인·영향·원인·주문데이터)
                 ▼
        ┌─────────────────────────────┐
        │   Codex 장애대응 산출물 플러그인     │
        ├─────────────────────────────┤
        │ ① 금감원 사고보고서 초안(별지2호) → EFARS 복붙/첨부 │
        │ ② 고객 공지문(실시간/복구, 3채널)             │
        │ ③ 보상 산정 검토표(통상손해 자동계산)          │
        │ ⑤ 경영진 속보 / 이사회 보고서(+보고대상 판정)   │
        │ ④ 대응 타임라인·시한 체크리스트              │
        └─────────────────────────────┘
                 │ 담당자가 검토·승인 후
                 ▼
        EFARS 입력 / 공지 게시 / 보상 통지 (사람이 실행)
```

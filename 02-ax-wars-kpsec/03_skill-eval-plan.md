# 스킬 평가 계획 (Task a) — 트리거링 + 기능 검증

## 0. 목표: 두 차원을 나눠 검증
| 차원 | 질문 | 방법 | 도구 |
|---|---|---|---|
| **① 트리거링** | 의도한 프롬프트에서 올바른 스킬이 발동하고, 무관/타스킬 프롬프트엔 발동하지 않는가 | 각 프롬프트를 `claude -p`로 실제 실행해 Skill 호출 여부 측정 | skill-creator `run_eval.py` |
| **② 기능 정확성** | 스킬이 발동한 뒤 스크립트를 올바른 인자로 실행하고 규정 정합 산출물을 내는가 | 스크립트 단위테스트(완료) + 대표 스킬 end-to-end 스팟체크 | `tests/test_plugin.py`(18) + `claude -p` |

## 1. 사전 검증 (cheap)
- `quick_validate.py`로 6개 SKILL.md 구조/프론트매터 검증.
- `tests/test_plugin.py` 재실행(회귀 없음 확인).

## 2. 트리거링 평가 방법
- `run_eval.py --eval-set <skill>.json --skill-path <skill dir> --runs-per-query 2`
- 동작: 스킬을 프로젝트 `.claude/commands/`에 **임시 등록** → `claude -p <query>` 실행 → Skill 툴 발동 감지 → query별 2회 반복해 발동률 산출. (전역 영구설치 불필요, 실행 후 정리)
- 스코프 격리: 플러그인 폴더에 로컬 `.claude/`를 두고 그 안에서 실행 → 홈 설정 오염 방지.

### 합격 기준(초안, 조정 가능)
- Positive(발동해야): 발동률 **≥ 0.8**
- Negative(발동 안 해야): 발동률 **≤ 0.2**

## 3. 스킬별 예시 프롬프트 (eval-set 설계)

각 스킬 eval-set = **자기 positive 3개** + **타스킬/무관 negative**(공유 풀에서). 아래는 positive 목록.

| 스킬 | Positive 프롬프트(발동해야 함) |
|---|---|
| **1. 금감원 보고서** (fss-incident-report) | ① "방금 MTS 장애 터졌어. 금감원에 낼 사고보고서 초안 만들어줘" ② "이번 체결지연이 EFARS 최초보고 대상인지 봐줘" ③ "전자금융사고 보고서 별지 제2호서식으로 작성해줘" |
| **2. 고객 공지** (customer-outage-notice) | ① "장애 났는데 고객 공지문 좀 써줘" ② "복구됐어, 정상화 안내 알림톡 문구 만들어줘" ③ "MTS 먹통 홈페이지 공지 초안 뽑아줘" |
| **3. 보상 산정** (compensation-calc) | ① "장애로 미체결된 주문 보상 얼마 줘야 해?" ② "보상 산정표 만들어줘" ③ "통상손해 계산해줘" |
| **4. 경영진·이사회** (exec-board-brief) | ① "이 장애 이사회까지 보고해야 해?" ② "경영진 속보 1보 작성해줘" ③ "CEO 보고용 요약 만들어줘" |
| **5. 개인정보 유출** (privacy-breach-filing) | ① "해킹으로 고객 개인정보 유출됐어, 신고 문서 만들어줘" ② "개인정보 유출 정보주체 통지문 써줘" ③ "72시간 유출 신고 서류 작성" |
| **6. 타임라인** (response-deadline-tracker) | ① "지금 뭐가 제일 급해? 보고 시한 알려줘" ② "장애 대응 진행상황 체크리스트 보여줘" ③ "남은 마감 정리해줘" |

### 공유 Negative 풀 (어떤 kpsec 스킬도 발동하면 안 됨)
- "리액트 컴포넌트 리팩터링 해줘"
- "이 파이썬 버그 디버깅 해줘"
- "주간 매출 대시보드 만들어줘"
- "회의록 요약해줘"

> 각 스킬 eval-set의 negative에는 **위 무관 풀 + 다른 스킬의 positive 일부**를 넣어 '교차 오발동'(예: 고객 공지 요청에 금감원 스킬이 뜨는지)도 측정.

## 4. 기능 정확성 스팟체크 (end-to-end)
대표 2~3개를 `claude -p`로 실제 실행(입력: `shared/incident.example.json`):
- 스킬1: "이 incident.json으로 금감원 최초보고서 만들어줘" → 출력에 **보고대상 판정 + 24h 시한 + EFARS 필드블록** 포함 확인.
- 스킬2: "복구 공지 만들어줘"(resolved_at 있는 예시) → **원인 포함 + 보상안내** 확인. resolved_at 제거 시 **복구 잠금** 확인.
- 스킬3: "보상 산정표" → **통상손해 80 USD / 108,000원** 산출 확인.

## 5. 실패 시 개선 루프
- 트리거링 미달 스킬 → `improve_description.py`로 description 최적화 후 재평가.
- 교차 오발동 → description에 경계 문구 추가(예: "보상 계산은 kpsec-compensation-calc, 이 스킬은 보고서 전용").

## 6. 비용·시간
- 트리거링: 6스킬 × (3 positive + 4 negative) × 2회 ≈ **84 헤드리스 claude 호출**. 수 분~십수 분, 토큰 사용.
- 기능 스팟체크: 3~4 호출.
- 절감 옵션: runs-per-query 1, negative 축소, 또는 우선 3개 핵심 스킬(1·2·3)만 먼저.

## 7. 산출물
- 스킬별 통과/실패표(positive/negative 발동률) + 교차 오발동 매트릭스
- 실패 스킬 description 개선안
- 기능 스팟체크 결과

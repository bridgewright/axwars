# 실데이터 검증 결과 (Layer 1 매핑 + 전환조정 커버리지)

엔진을 실제 DART/공개자료로 어디까지 검증할 수 있는지 정직하게 정리한다.

## 1. Layer 1 매핑 — 실제 K-IFRS 공시로 검증 ✅

`analysis/validate_mapping_vs_dart.py` — 우리 K-GAAP→K-IFRS 매핑의 IFRS 타깃 계정이 실제 상장사 K-IFRS 공시(OpenDART `fnlttSinglAcntAll`)에 존재하는지 대조.

- 대조 대상: 한온시스템·삼성전기·CJ제일제당 2023 연결/별도 (실제 공시 계정 **318개** 합집합).
- 결과: **우리 IFRS 타깃 37개 중 35개(95%)가 실제 공시에 존재.**
  - 확인: 현금및현금성자산·매출채권·재고자산·유형자산·무형자산·영업권·순확정급여부채·사용권자산·당기손익-공정가치측정금융자산·계약부채·이연법인세자산/부채·차입금·사채 등.
  - 미발견 2개(손실충당금·상각후원가측정금융자산)는 요약재무제표에서 **통합·차감 표시**되어 별도 line이 없는 정상 케이스.
- **결론: 매핑의 IFRS 계정 체계는 실제 공시와 정합.**

## 2. 전환조정(Layer 2) 숫자 — 개별기업 실사례 자동추출은 데이터 벽 ⚠️

목표: 실제 전환상장사의 IFRS 1101 전환조정표(종전 자본→조정→K-IFRS 자본)를 정답셋으로 대조.

시도·결과:
- 삼성전자·LG전자·현대차·기아·한온시스템·삼성전기·롯데케미칼·CJ제일제당·LG화학 (9개사) × 사업보고서/별도감사보고서(F001)/연결감사보고서(F002) × FY2010·FY2011을 스캔.
- **전환주석을 기계추출 못 함.** 근본 원인 2가지:
  1. **시대 포맷:** 2011년 전환기 공시(감사보고서·주석)는 **HWP/PDF 첨부** 형식이라 OpenDART `document.xml`의 텍스트 추출로 안 잡힘(구조화 XBRL/DSD 이전).
  2. **입력 비공개:** 공시되는 건 요약 전환조정표이지 **입력 시산표 전체가 아님** → 엔진에 "실제 입력"을 넣어 "실제 출력"과 대조하는 완전 end-to-end 재현은 공개 데이터로 불가.

→ **개별기업 숫자까지 맞춘 검증은 공개 데이터 한계.** 대신 두 가지로 신뢰를 확보:
- **조정 규칙·기준서 인용의 정확성**(아래 3) — 실제 공개 기준서·비교가이드 근거.
- **다조정 전환 실증**(`gaap-ifrs/tests/fixtures/transition_*` + `analysis/validate_transition_demo.py`) — 독립 수기계산 정답셋과 4개 조정 전건 일치(PASS).

## 3. 조정 커버리지 — 표준 K-IFRS 전환조정 유형 대비

IFRS 1101 전환에서 실무상 빈번한 조정 유형과 우리 엔진 커버리지:

| 표준 전환조정 유형 | 기준서 | 엔진 커버 |
|---|---|---|
| 대손 발생손실 → 기대신용손실(ECL) | K-IFRS 1109 | ✅ compute_ecl |
| 운용리스 온-BS(사용권자산·리스부채) | K-IFRS 1116 | ✅ compute_lease |
| 유형자산 재평가모형 | K-IFRS 1016 | ✅ compute_revaluation |
| 개발비 자본화 요건 차이 | K-IFRS 1038 | ✅ compute_devcost |
| 확정급여채무(보험수리적) | K-IFRS 1019 | ⚠️ 매핑만(측정조정 미구현) |
| 금융상품 분류·측정 | K-IFRS 1109 | ⚠️ 매핑만 |
| 수익 인식시점(계약부채) | K-IFRS 1115 | ⚠️ 매핑만 |

→ 4개 고빈도 측정조정을 자동 계산, 나머지는 매핑·진단으로 표면화(추가 구현 여지 명시).

## 종합

- **조정(Layer 2): 규칙·인용은 공개 기준서 근거로 정확, 다조정 실증 PASS. 개별기업 숫자 재현은 공개 데이터 한계.**

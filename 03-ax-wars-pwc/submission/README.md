# pwc-gaap-ifrs-suite — 삼일PwC 회계기준(GAAP↔K-IFRS) 전환 자문 자동화

여러 나라 회계기준으로 된 시산표를 **한국채택국제회계기준(K-IFRS)으로 전환**하는 자문을, **원문 근거를 그대로 인용하는 두 스킬**로 자동화하는 Codex 플러그인. 시산표를 넣으면 K-IFRS 재무제표와 전환조정 명세서를 만들어 주는 **변환 도구**, 회계기준 원문을 검색해 원문 인용으로만 답하는 **상담 챗봇**으로 구성. 최종 숫자는 결정론 코드가 계산하고, 규정 근거는 지어내지 않고 코퍼스 원문에서 가져옴 — 감사·자문 산출물에 틀린 조항 인용이 들어가는 위험을 원천 차단.

---

## 심사 5문항

### 1. 무엇을, 누가, 어떤 상황에서 쓰나요? *(800자 이내)*

**[무엇을]** 삼일PwC가 여러 나라 회계기준을 한국채택국제회계기준 K-IFRS로 바꾸는 자문을 돕는 Codex 플러그인. 스킬은 두 개. 첫째는 시산표를 넣으면 K-IFRS 재무제표와 전환조정 명세서, 계정별 차이, 손익 및 자본 영향까지 엑셀과 보고서로 만들어 주는 변환 도구(gaap-ifrs-converter). 둘째는 회계기준 원문을 찾아 원문 그대로만 인용해 답하는 RAG 기반 상담 챗봇(gaap-standards-qa). 두 스킬은 지식베이스로 적재한 베트남, 중국, 한국 GAAP과 K-IFRS 원문을 MCP로 함께 활용.

**[누가]** 삼일 회계감사본부에서 회계기준 전환 자문을 맡는 담당자. 주로 주니어부터 매니저까지.

**[어떤 상황]** 첫째, 비상장 회사가 상장을 준비하며 일반기업회계기준을 K-IFRS로 바꿔야 하는 경우. 둘째, 국내 대기업이 베트남과 중국 같은 해외 자회사의 현지 기준을 모회사 K-IFRS로 합쳐 연결 재무제표를 만드는 경우.

**[타겟 페인포인트]** 받은 시산표를 K-IFRS 계정으로 다시 나누고, 대손과 리스, 자산 재평가 같은 차이를 조정하는 일. 지금은 현지 기준과 K-IFRS를 모두 아는 드문 시니어에게만 일이 몰려, 시니어의 검토를 기다리는 동안 진도가 정체되는 병목.

**[무엇이 달라짐]** 이 플러그인이 있으면 주니어가 명령어 한 줄로 초안과 조항 근거, 손익 및 자본 영향을 바로 확보. 필요한 자료가 없는 항목은 판단 필요로 표시되어 실수 예방. 챗봇은 산출물에 틀린 조항 번호나 문구가 들어가는 위험을 차단. 사람은 검토와 판단이라는 더 가치 높은 일에 집중.

### 2. 왜 이 문제를 선택했나요? *(800자 이내)*

**[문제 배경]** 삼일 회계감사본부의 핵심 이슈는 감사가 누구나 하는 흔한 일이 되어 값이 계속 떨어지는 현상. 감사 수임료는 내려가는데 인건비는 매출보다 빠르게 늘어, 영업이익률이 몇 년 만에 4.29%에서 1.60%로 크게 하락.

**[전략 방향]** 그래서 우리 목표는 감사 비용 절감이 아니라 Assurance 내 고마진 자문의 확대. 감사는 이미 값이 낮고 엑셀 매크로와 자체 도구로 자동화도 많이 된 영역. 대신 이익이 큰 자문 업무의 비중을 늘리고, 그 자문을 AI로 훨씬 싸게 수행. 곧 드문 시니어의 전문성을 누구나 쓰게 만드는 방향이며, 인재전쟁 주제와 정합.

**[왜 이 자문인가]** 그 자문 가운데 회계기준 전환을 고른 이유는 세 가지. 첫째, 삼일이 실제로 파는 서비스. 둘째, 양쪽 기준을 다 아는 전문가가 드물어 AI 효과가 큰 분야. 셋째, 기준 원문과 비교 자료가 공개되어 지어내지 않고 근거 제시 가능.

**[사용자 병목]** 담당자는 계정을 다시 나누고 차이를 조정할 때마다 두 기준을 모두 아는 시니어의 확인을 대기. 특히 상장 전환에서는 계정과 손익 구조가 크게 바뀌어, 한 곳만 잘못 조정해도 뒤 단계까지 재작업 발생. 시즌에는 이 대기와 재작업이 반복되어 초안에 시간 소모.

**[수요 근거]** 2022년부터 해외 자회사까지 묶어 연결 재무제표를 만들 의무가 생겨, 자회사가 많은 중국과 베트남 기준 전환 수요 증가.

### 3. 플러그인은 어떻게 작동하나요? *(1000자 이내)*

**[절차]** 변환 도구는 시산표를 받아 표준 형태로 정리. 이어서 계정을 K-IFRS 체계로 다시 나누고, 대손과 리스, 유형자산 재평가, 개발비, 확정급여, 금융상품 여섯 가지 측정 차이를 조정. 각 조정은 차변과 대변으로 나눠 자산과 부채, 자본의 균형을 맞춰 계산. 마지막으로 K-IFRS 재무제표와 전환조정 명세서, 손익 및 자본 영향, 계정별 상세 보고서를 순서대로 산출.

**[지식]** 어떤 기준의 어느 조항을 쓸지는 규칙 파일에 정리해 보관. 그 조항의 실제 문장은 상담 챗봇이 쓰는 원문 데이터에서 그대로 가져와 보고서에 반영. 원문 데이터에는 한국채택기준과 일반기업회계기준, 중국과 베트남 기준 원문 약 1만 문단을 포함. 검색은 단어가 겹치는 방식과 뜻이 비슷한 방식을 함께 사용해 정확도 확보. 규칙과 원문을 한곳에 모아 두 스킬이 같은 근거를 공유하고, 변환 도구의 조항 근거가 실제 원문과 자동으로 대조.

**[판단 기준]** 숫자는 사람이 정한 규칙에 따라 코드가 계산. 숫자와 조항 문장은 AI 생성 대상에서 제외. 상담 챗봇도 먼저 원문을 검색하고, 찾은 문단만 출처와 함께 인용. 답변은 원문 인용을 먼저 두고, 뜻풀이와 다른 나라 기준 비교는 라벨로 나눠 제시. 비교 대상 기준을 못 찾으면 대응 규정 없음으로 표기. 단순 조회에는 원문과 짧은 해석을 주고, 분석 요청에는 실무 적용과 다른 나라 기준 비교까지 단계로 확장.

**[막힐 때]** 필요한 자료가 없으면 금액을 지어내지 않고 판단 필요로 표시. 원문에서 근거를 못 찾으면 근거 없음으로 답변. 원문 데이터에 아직 없는 조항은 요약본임을 밝혀 구분. 검색 기능이 일부만 되는 환경에서도 자동으로 더 단순한 방식으로 전환해 계속 동작하고, 어떤 방식으로 답했는지 항상 안내.

### 4. AI를 어떻게 썼나요? *(800자 이내)*

**[AI에 맡긴 것]** AI와 함께 PwC의 사업 영역과 주요 서비스, 재무를 조사. 특히 감사와 딜, 컨설팅 부문별 매출과 영업이익 변화를 확인. 그 밖에 지저분한 엑셀에서 계정 이름을 맞추는 초안, 문서에서 문단을 잘라내는 규칙 초안, 검색을 붙이는 반복 코드도 AI가 작성.

**[직접 판단한 것]** 리서치 결과를 바탕으로 구조적 문제를 직접 정의. 감사 수임료는 낮아지는데 매출을 지키려 인력을 늘려 수익성이 무너지는 구조. 여기서 전략 방향과 실제로 풀 세부 문제인 회계기준 전환 자문을 직접 선정. 최종 숫자도 AI가 아니라 사람이 정한 규칙과 코드로 계산.

**[막힌 지점과 해결]** 처음에는 시산표만 받아 변환하는 도구부터 제작. 그러다 이 용역의 본질이 회계기준 원문을 오류나 지어냄 없이 그대로 가져와 분석하는 데 있다는 점을 인식. 그래서 원문을 검색해 인용하는 RAG 챗봇을 먼저 구축하고, 변환 도구도 그 원문 검색 기반 위에서 반드시 원문을 참조하도록 다시 설계. 한글 파일에서 원문 띄어쓰기가 사라지던 문제도 원문 종류를 바꿔 해결.

**[거부한 AI 제안]** 첫째, 조정을 자본 영향 숫자 하나로만 두자는 제안 거부. 차변과 대변으로 나눠야 자산과 부채, 자본의 균형 확보. 둘째, 검색용 글과 인용용 원문을 한 벌로 저장하자는 제안 거부. 인용이 원문과 한 글자도 달라선 안 되기 때문. 셋째, 두 검색 점수를 그냥 더하자는 제안 거부. 크기가 서로 달라 순위 기준으로 합치는 방식 선택.

### 5. 어떻게 검증했나요? *(800자 이내)*

**[입력에서 결과 예시]** 변환 도구는 일반기업회계기준 시산표와 보조자료를 넣으면 여섯 개 조정을 계산해 자본총계를 5천만에서 5,634만으로 산출하고, 각 조정의 원문 근거와 분개 효과를 보고서에 기록. 챗봇은 리스 인식을 물으면 K-IFRS 1116호 22문단 원문을 그대로 인용해 답변.

**[정상과 예외]** 정상은 위처럼 계산과 인용. 예외는 보조자료가 없으면 계산 대신 판단 필요로 표시, 검색 결과가 없으면 근거 없음으로 답변, 검색이 일부만 되는 경우도 미리 만든 상황으로 확인.

**[의심하고 되짚음]** 변환 도구는 인풋인 실제 회사 시산표를 구할 수 없어, 회계기준과 일반 사례로 입력 예제를 직접 만들어 스킬을 돌리고 결과를 검토해 규칙을 고치는 방식으로 검증. 챗봇은 다 만들었다고 판단한 뒤 실제로 써 보니 인용 원문이 문단 단위로 제대로 나뉘지 않은 것을 의심하고 발견, 원인을 하나씩 되짚어 재진단.

**[테스트하며 고친 점]** 처음에는 일부만 조사해 고치려 했으나 전수조사로 바꾸자 훨씬 많은 결함 발견. 새 분할 방식으로 다시 나눌 때도 한 번에 끝내지 않고 조금씩 나눠 중간중간 확인하며 반영. 그 결과 원문에 페이지 번호나 절 제목이 섞이던 문제까지 제거. 자동 검사 변환 도구 47개와 챗봇 130개 항목으로 아웃풋 고정.

**[아직 부족한 점]** 시산표 조정 관련해 수익 인식과 자산 손상 같은 남은 조정은 확장 필요. 미국 회계기준 원문은 사이트 차단으로 아직 미포함. 모든 결과물은 전문가 검토용 초안.

## 구성 — 1개 플러그인 = 스킬 2 + MCP 서버 1 + 공유 코퍼스

두 스킬은 같은 원문 코퍼스를 공유한다. 한쪽은 그 원문을 **계산 근거**로, 다른 한쪽은 **대화 근거**로 쓴다.

| 구성 요소 | 디렉터리 | 무엇을 하나 | 근거 |
|---|---|---|---|
| **스킬 1 · 변환 도구** `gaap-ifrs-converter` | `src/skills/gaap-ifrs-converter/`, `src/gaap-ifrs/` | 시산표 → K-IFRS 재무제표·전환조정 명세서·계정별 차이분석·손익/자본 영향(Excel·Markdown·JSON) | 계정매핑·6조정 규칙(`data/*.json`) + 조항 원문은 코퍼스에서 grounding |
| **스킬 2 · 원문 챗봇** `gaap-standards-qa` | `src/skills/gaap-standards-qa/` | 회계기준 질의 시 원문 verbatim 인용 + 계층형(원문→해석→실무→GAAP비교) 답변 | 로컬 MCP 하이브리드 검색 |
| **MCP 서버** `gaap-standards` | `src/gaap_standards_mcp/`, `.mcp.json` | `search_standards`·`get_paragraph`·`get_context`·`list_standards` 4개 도구 | 코퍼스 10,922문단 + 벡터 인덱스 |

## 스킬별 상세 동작

**스킬 1 — 변환 도구 (`gaap-ifrs-converter`)**
파이프라인은 `parse(시산표→표준형) → map(Layer1 재분류) → adjust(Layer2 측정조정) → build(IFRS BS/PL) → reconcile(자본 전환 브릿지) → impact → report`. Layer 1은 시산표만으로 전 계정을 K-IFRS 표시체계로 매핑하고, Layer 2는 **대손·리스·유형자산 재평가·개발비·확정급여·금융상품** 여섯 조정을 **복식부기 분개**로 계산(자산=부채+자본 균형을 코드가 강제). 각 조정의 IFRS 근거는 규칙 파일의 포인터(`ifrs_ref`)가 가리키는 **코퍼스 원문을 그대로 인용**하며(엔진-side·결정론), 코퍼스에 없으면 손으로 쓴 요약을 "큐레이션 요약"으로 라벨해 폴백. 매핑 규칙이 없는 계정이나 보조자료가 없는 조정은 금액을 지어내지 않고 **판단 필요(flagged)** 로 표기. 산출물은 `out/`에 `ifrs_financials.xlsx`·`reconciliation.xlsx`·`impact_analysis.xlsx`·`difference_analysis.md`·`result.json`.

**스킬 2 — 원문 챗봇 (`gaap-standards-qa`)**
회계기준 질문에는 **먼저 MCP를 검색**하고, 검색된 문단 원문만 근거로 삼아 답한다. 규정 내용(사실)은 원문 인용 + `[출처]` 표기, 그 위에 얹는 해석·다국가 비교는 `(일반 해설)` 라벨로 원문과 분리한다. 단순 조회에는 원문과 짧은 해석을, 분석 요청에는 실무 적용과 GAAP 비교까지 계층으로 확장한다. 근거를 못 찾으면 **"원문에서 근거를 찾지 못함(근거 없음)"** 이라 답하고 지어내지 않는다. 검색은 키워드(BM25)와 의미(벡터)를 순위로 융합하며, 임베딩·MCP가 불가하면 BM25 단독(degraded) → 내장 스크립트(no-mcp)로 3단 폴백하고 어느 경로로 답했는지 항상 고지한다.

## 데이터 · 코퍼스

- `src/corpus/`에 **4개 소스 GAAP 10,922문단** — K-IFRS(63기준서·6,115) · 일반기업회계기준(36장·2,001) · 중국 CAS(95문서·1,626) · 베트남 VAS(26기준서·1,180) — 을 각 나라 **공식 원문 verbatim**으로 적재(zstd 압축 `*.jsonl.zst` + faiss 벡터 인덱스 + `manifest.json`).
- 인용용 원문(`text`)과 검색·임베딩용 정규화 텍스트(`text_norm`)를 **이중 저장** — 인용이 원문과 한 글자도 달라지지 않게.
- 다국어 임베딩이라 **교차언어 검색** 가능(중국어 질의로 중국 기준 원문 검색). 베트남 VAS 출처는 발행 결정문(Bộ Tài chính, Quyết định) 기준.
- **US GAAP만 원격 확장 지점**(asc.fasb.org 봇 차단으로 원문 zip 내장 불가). 트랙 1은 US GAAP 계정매핑까지는 지원, 원문 grounding은 코퍼스 적재 후.

## 설치 · 실행

- **Codex 설치(로컬 마켓플레이스):** `src/`가 플러그인 루트. 마켓플레이스를 통해 `codex plugin marketplace add <경로> && codex plugin add pwc-gaap-ifrs-suite@<마켓플레이스>`로 설치하면 스킬 2종 + MCP 서버가 자동 등록된다(`installed, enabled` 확인).
- **의존성:** `cd src && pip install -e .`(mcp·rank-bm25·numpy·faiss-cpu·sentence-transformers·zstandard). 없으면 챗봇은 자동으로 BM25 단독(degraded)으로 동작.
- **MCP 서버 직접 기동:** `python -m gaap_standards_mcp`(`.mcp.json`에 등록됨). MCP 클라이언트 없이 조회: `python -m gaap_standards_mcp.entry corpus "리스 사용권자산 인식"`.
- **변환 도구:** `cd src/gaap-ifrs && gaap-ifrs convert --input <시산표.csv|xlsx> --source-gaap K-GAAP --extra <보조자료.json> --out out/`.
- **테스트:** 트랙 1 `cd src/gaap-ifrs && python -m pytest -q`(47) · 트랙 2 `cd src && python -m pytest -q`(130).

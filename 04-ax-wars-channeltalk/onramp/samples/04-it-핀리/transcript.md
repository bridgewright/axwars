# 예시 인터뷰 트랜스크립트 — 핀리 (구독 핀테크) · 역할: IT/시스템 담당

> 테스트용 가상 인터뷰(격식체). IT 담당이라 시스템·연동·보안 축이 두텁고, 상담 업무·경영 지표는 상대적으로 얕게 남는다.

**인터뷰어:** 안녕하세요. 오늘 시간 내주셔서 감사합니다. 지금 상담이 실제로 어떻게 운영되는지 편하게 말씀해 주시면 됩니다. 지금 주문이나 예약, 회원 관련해서는 어떤 시스템을 쓰고 계신가요?

**현업(IT 담당):** 저희는 구독 서비스라 결제·구독 관리 시스템이 핵심이에요. 회원이랑 구독 상태는 자체 구축한 백엔드에서 관리하고, 결제는 외부 PG를 붙여서 씁니다.

**인터뷰어:** 그 시스템들이 하나로 통합되어 있나요, 아니면 나뉘어 있나요?

**현업:** 회원·구독은 저희 백엔드 하나로 통합돼 있고, 결제·환불만 PG 쪽이라 분리돼 있어요.

**인터뷰어:** 외부에서 프로그램으로 호출할 수 있는 창구, 즉 API가 제공되나요? 문서화는 되어 있나요?

**현업:** 자체 백엔드는 내부 REST API가 있어요. 문서화도 웬만큼 돼 있고요. 구독 조회나 상태 변경은 그걸로 됩니다. 다만 환불은 PG API를 거쳐야 해서 거긴 저희가 마음대로 못 해요.

**인터뷰어:** 그 시스템은 직접 구축하셨나요, 외부 솔루션인가요? 외주라면 기능을 추가하실 때 그쪽에 요청하셔야 하나요? 기간은 얼마나 걸리나요?

**현업:** 회원·구독 백엔드는 저희가 직접 만들어서 기능 추가는 저희가 바로 해요. PG는 외부라 환불 관련 흐름을 바꾸려면 PG 규격에 맞춰야 하고, 검토에 2~3주는 봐야 해요.

**인터뷰어:** 채널톡이 구독 취소 같은 작업을 자동으로 하려면, 그쪽에서 무엇을 열어 주시거나 만들어 주셔야 할 것 같으신가요?

**현업:** 구독 조회랑 취소는 저희 내부 API에 엔드포인트를 열어드리면 돼요. 그건 어렵지 않아요. 환불 금액 계산까지 자동으로 하려면 PG 연동이 얽혀서 그건 좀 더 봐야 하고요.

**인터뷰어:** 고객이나 주문 정보를 연동하실 때 걸리는 보안이나 권한 이슈가 있으신가요?

**현업:** 핀테크라 개인정보랑 결제정보 규제가 빡세요. 채널톡에 결제정보 원문이 넘어가면 안 되고, 최소한의 필드만 토큰화해서 주고받아야 해요. 접근 권한이랑 로그도 남겨야 하고요.

**인터뷰어:** 상담 문의 중에는 어떤 게 많은지 혹시 아시나요?

**현업:** 정확히는 CS팀이 알 텐데, 구독 취소랑 환불, 결제 실패 문의가 많다고 들었어요.

**인터뷰어:** 잘 들었습니다. 회원·구독은 자체 API로 연동이 수월하고, 환불은 PG 규격·보안 때문에 대응 개발과 검토가 필요하다는 말씀으로 이해했습니다. 상담량·지표는 CS팀 확인이 필요하겠네요. 감사합니다.

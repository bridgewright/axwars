# 고객 페인 + 제품 제안서 — 핀리 (구독 핀테크)

> 본진 프로덕트팀 전달용. 근거: intake 음성 인터뷰(`samples/04-it-핀리/transcript.md`).

## 0. 고객 페인포인트 (실제 인용)
- "구독 취소·환불·결제실패 문의가 많다고 전해 들음(정확한 규모는 CS팀 소관)" — 빈도 미확인, 미해결 원인: 환불은 PG 규격·보안이 얽혀 자동화가 어려움

## Problem Statement
구독 취소·환불·결제실패 문의가 많다고 전해 들음(정확한 규모는 CS팀 소관) — 반복·정형 문의가 피크에 폭증하는데 실제 처리가 사람에 묶여 있다.

## Solution
- 구독 조회·취소는 내부 API로 자동, 환불은 단계적

## User Stories
1. As a 고객사 CS 담당, I want 알프가 구독 조회/취소를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 환불를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다

## Implementation Decisions
- 구독 조회/취소: tier `system_task`, 백엔드 자체 회원·구독 백엔드, API yes — 파일·코드는 명시하지 않음
- 환불(금액 계산 포함): tier `system_task`, 백엔드 외부 PG, API yes — 파일·코드는 명시하지 않음

## Testing Decisions
- 외부 동작(고객 요청 → 처리 결과)만 검증한다. 구현 세부는 테스트하지 않는다.
- 유사 선례: 기존 태스크 자동화(주문취소·교환) 케이스의 종단 시나리오.

## Out of Scope
- 이번 인터뷰에서 확인되지 않은 시스템·업무(아래 미해결 질문 참조).

## Further Notes
- 환불 금액 계산 자동화 시 PG 연동 범위·기간(2~3주 검토) 확정
- 결제/개인정보 보안 요건(토큰화·권한·로그)에 대한 채널톡 측 지원 범위
- 상담량·문의 유형 비중·성공 지표 — CS팀/경영진 인터뷰 필요

## 제품 갭 태그 분류 (누적 시 우선순위 신호)
- `[action_task]` × 1건: 구독 조회랑 취소는 저희 내부 API에 엔드포인트를 열어드리면 돼요
- `[handoff_quality]` × 1건: 채널톡에 결제정보 원문이 넘어가면 안 되고, 최소한의 필드만 토큰화해서 주고받아야 해요

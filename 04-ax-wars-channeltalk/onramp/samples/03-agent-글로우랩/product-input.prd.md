## 0. 고객 페인포인트 (실제 인용)
- "피부 트러블 클레임 한 건에 주문조회·성분표 검색·교환정책 확인·어드민 교환접수·품질팀 전달까지 여러 화면을 오간다" — 빈도 클레임은 소수, 성분·사용법 문의는 다수, 미해결 원인: 성분표 문서가 폴더마다 흩어져 있고 교환은 어드민 처리가 필요
- "성분표·사용법을 노션 여기저기서 찾아 복붙하는데 신입은 위치를 모른다" — 빈도 상시, 미해결 원인: 지식이 흩어져 있고 정리가 안 됨
- "'임신 중 사용 가능한가요' 같은 애매한 질문은 품질팀에 확인하느라 답이 늦고, 고객이 질문을 짧게 하면 되물어야 한다" — 빈도 상시, 미해결 원인: 모호한 질문의 의도 파악과 예외 판단이 필요

## Problem Statement
피부 트러블 클레임 한 건에 주문조회·성분표 검색·교환정책 확인·어드민 교환접수·품질팀 전달까지 여러 화면을 오간다 — 반복·정형 문의가 피크에 폭증하는데 실제 처리가 사람에 묶여 있다.

## Solution
- 조건부 교환 접수 자동화 + 성분·사용법 즉시 응답
- 알프가 문서에서 바로 찾아 답변
- 알프가 되묻기로 맥락을 파악

## User Stories
1. As a 고객사 CS 담당, I want 알프가 성분/사용법 안내를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 재입고/배송 안내를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 조건부 교환 접수를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다

## Implementation Decisions
- 성분/사용법 안내: tier `no_integration`, 백엔드 노션 등 문서, API n/a — 파일·코드는 명시하지 않음
- 교환 접수: tier `system_task`, 백엔드 주문 어드민(현장은 버튼만 사용), API unknown — 파일·코드는 명시하지 않음

## Testing Decisions
- 외부 동작(고객 요청 → 처리 결과)만 검증한다. 구현 세부는 테스트하지 않는다.
- 유사 선례: 기존 태스크 자동화(주문취소·교환) 케이스의 종단 시나리오.

## Out of Scope
- 이번 인터뷰에서 확인되지 않은 시스템·업무(아래 미해결 질문 참조).

## Further Notes
- 교환 접수 뒷단 시스템의 API/연동 가능 여부 — 개발팀 확인 필요
- 팀 규모·하루 상담량 등 정량 수치 — CS 리더 인터뷰 필요
- 성공 지표·목표 — 경영진/리더 인터뷰 필요

## 제품 갭 태그 분류 (누적 시 우선순위 신호)
- `[action_task]` × 1건: 조건 맞으면 알프가 알아서 접수까지 해주면 저희가 진짜 편해져요
- `[reask_context]` × 1건: 고객이 질문을 짧게 하시면 뭘 원하시는지 되물어야 하고요
- `[knowledge_authoring]` × 1건: 문서가 여기저기 흩어져 있어서 신입은 어디 있는지도 잘 몰라요

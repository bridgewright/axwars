# 고객 페인 + 제품 제안서 — 트립메이커 (여행 액티비티 예약 플랫폼)

> 본진 프로덕트팀 전달용. 근거: intake 음성 인터뷰(`samples/02-exec-트립메이커/transcript.md`).

## 0. 고객 페인포인트 (실제 인용)
- "성수기 예약 변경·취소 문의가 폭주하면 응대가 늦어지고 별점으로 바로 이어진다" — 빈도 성수기 집중, 미해결 원인: 인력 증원만으로 감당 불가, 예약 시스템 연동 여부 미확인
- "응대가 늦으면 고객이 예약을 취소해 매출이 샌다" — 빈도 성수기, 미해결 원인: CS가 매출 방어선인데 속도를 못 냄

## Problem Statement
성수기 예약 변경·취소 문의가 폭주하면 응대가 늦어지고 별점으로 바로 이어진다 — 반복·정형 문의가 피크에 폭증하는데 실제 처리가 사람에 묶여 있다.

## Solution
- 예약 변경·취소를 자동 처리해 성수기 병목 해소
- 빠른 응대로 이탈 방지

## User Stories
1. As a 고객사 CS 담당, I want 알프가 예약 변경를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 예약 취소를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 다국어 1차 응대를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다

## Implementation Decisions
- 예약 변경/취소: tier `system_task`, 백엔드 외부 예약 엔진(솔루션), API unknown — 파일·코드는 명시하지 않음

## Testing Decisions
- 외부 동작(고객 요청 → 처리 결과)만 검증한다. 구현 세부는 테스트하지 않는다.
- 유사 선례: 기존 태스크 자동화(주문취소·교환) 케이스의 종단 시나리오.

## Out of Scope
- 이번 인터뷰에서 확인되지 않은 시스템·업무(아래 미해결 질문 참조).

## Further Notes
- 예약 엔진(외부 솔루션)이 변경·취소 API를 제공하는지 — 개발팀 확인 필수
- 성수기 실제 상담량·팀 규모 수치
- 현재 FAQ/도큐먼트 정비 상태 (실무자 인터뷰 필요)
- 다국어 대상 언어 우선순위

## 제품 갭 태그 분류 (누적 시 우선순위 신호)
- `[metric_redefine]` × 1건: 자동해결률 숫자에 집착하고 싶진 않습니다
- `[action_task]` × 1건: 예약 변경이나 취소 문의가 폭주하면 응대가 늦어져요
- `[multilingual]` × 1건: 다국어 응대가 되면 그 시장이 더 열릴 거예요

# 배포 계획서 — 무브온 (패션 이커머스)

> 인터뷰 대상: `cs_lead` · 회사 규모: enterprise · 작성: 2026-07-06

## 1. 도입 적합성
- 팀 규모: 5명 · 하루 상담량: 평시 약 400건, 피크 2,000건+ · 채널: 채팅, 이메일
- 기준선(1인 하루 30건+ · 매크로 답변 5건+) 대비 도입 적합성 판단 필요

## 2. 자동화 범위 (우선순위 순)
- **배송조회** (적합도 high, 우선순위 1) — 현재: 택배사 사이트 수기 조회
- **재입고문의** (적합도 high, 우선순위 2) — 현재: 매크로 복붙
- **주문취소** (적합도 mid, 우선순위 3) — 현재: 어드민에서 상담사가 취소
- **교환/반품 접수** (적합도 mid, 우선순위 4) — 현재: 어드민 확인 후 상담사 처리

## 3. 연동 가능성 진단 (해결률 상한을 가르는 핵심)
- **배송조회** — tier `workflow` · 시스템 택배사 조회(separate) · API yes · vendor · 공수 낮음(기성 함수)
- **재입고문의** — tier `no_integration` · 시스템 없음(FAQ로 충분)(n/a) · API n/a · n/a · 공수 없음
- **주문취소** — tier `system_task` · 시스템 자체 주문 어드민(integrated) · API unknown · inhouse · 공수 미정(개발팀 확인 필요)
- **교환/반품 접수** — tier `system_task` · 시스템 자체 주문 어드민 + 외주 WMS(separate) · API unknown · vendor · 공수 외주 WMS 대응 필요(기간 미정)

> tier `system_task`가 있으면 백엔드 연동이 해결률 상한을 결정한다. `no_integration`만이면 FAQ/RAG 수준(해결률 상한 낮음).

## 4. 지식 준비도 & 정비 공수
- FAQ 추정 50개 · 문서 교환·반품 정책 등 8건 · 갭 FAQ가 단어형 → 문장형 전환 필요 · 공수 약 3시간 + 테스트

## 5. 단계적 롤아웃
- 빠른 효과 지점 먼저 → 확장. 권장 순서: 배송조회 → 재입고문의 → 주문취소 → 교환/반품 접수

## 6. 성과 지표 설계 (해결률 단독 금지)
- 목표: 프로모션 피크 문의 적체 해소, 재인입률 하락, 응답시간 단축
- 성공 정의: 자동해결률 절대치보다 재인입률·CSAT를 함께 본다 · 해결률 함정 인지: True
- 지표 묶음: 해결률 × 재인입률 × 응답시간 × 인력 절감 × CSAT

## 7. 조직·상담사 변화관리
- 역할 전환: 단순 응대 → 상품정보 세팅·반품 사유 VoC 분석·품질 체크 · 변화관리 리스크: 낮음 (리더가 역할 전환에 우호적)

## 8. 리스크 & 배포 전 미해결 질문 (사전 단서)
- 자체 주문 어드민이 외부 API를 제공하는지 (개발팀 확인)
- 외주 WMS 연동에 대응 개발이 얼마나 걸리는지
- 피크 프로모션 일정과 배포 완료 목표일 정합성

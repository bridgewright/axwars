## ⚡ 결론 먼저 — 권고

**조회·취소·교환접수(자체 API·2주)로 1차 도입해 피크 반복 문의를 빠르게 걷어내고, 회수·환불(외주 WMS·PG·2~3주)은 보안 스펙 확정 후 2차로 확장하라**

문의의 절반 이상이 배송조회·재입고·소재문의 같은 반복·정형이라 즉시 효과가 크고, 자체 커머스 백엔드에 내부 API가 잘 갖춰져 있어 조회·취소·교환접수는 약 2주면 연동된다. 반면 손이 가장 많이 가는 회수·환불은 외주 WMS·PG 규격과 부분환불 검증 때문에 2~3주가 더 걸려 해결률 상한을 가르므로, 무리해서 한 번에 붙이기보다 2차로 미루는 것이 합리적이다.

- **준비도 진단**: green(1차) / yellow(2차) — 조회·취소·교환접수는 즉시 착수 가능, 회수·환불은 보안 스펙과 WMS 연동 기간 확정 후
- **먼저 볼 리스크**: 회수 외주 WMS 연동 2~3주 + 환불 부분계산 검증 복잡; 결제·개인정보 토큰화·로그·권한 스펙 미확정 시 보안 검토에서 지연; 피크 시즌 일정과 2차 확장 타이밍 충돌

## 1. 왜 지금인가 — 현장의 목소리

> "지난 시즌오프 프로모션 때 하루 2000건 넘게 들어와서, 5명이 밤 11시까지 붙어도 다음 날 아침 300건씩 밀려 있었어요"
>
> — 대형 프로모션·라이브방송마다 (분기 1~2회) · 막힌 이유: 사람을 그만큼 못 뽑고, 단기 알바는 정책을 몰라 실수가 잦아 검수에 더 손이 감 · 원하는 것: **피크에도 앞단에서 반복 문의가 자동 처리되어 인력 증원 없이 감당**

> "사이즈 교환 한 건에 주문 상태 조회·재고 확인·회수 신청·안내까지 5~7분, 하루 100건 넘으면 사람 하나가 종일 매달려요"
>
> — 상시, 환절기 급증 · 막힌 이유: 재고 유무에 따라 교환/환불 분기가 갈리는데 그 판단이 시스템 값을 봐야 결정됨 — 답변만으로 불가 · 원하는 것: **조건(7일 이내·택 미개봉·재고 있음)을 알프가 시스템으로 판단해 교환접수까지 자동 처리**

> "재입고 문의는 하루 수십 번 같은 답을 복붙하는데, FAQ가 단어형이라 '이거 언제 다시 들어와요' 같은 문장을 알프가 잘 못 잡아요"
>
> — 상시 · 막힌 이유: FAQ가 단어 위주로 짜여 자연어 매칭이 약함 · 원하는 것: **재입고 안내를 알프가 단독으로 처리**

> "'이거 교환돼요'처럼 짧게만 물어오면 어떤 주문인지·왜 교환하려는지 사람이 다시 되물어야 하는데, 알프는 그걸 못하고 '확인 어렵습니다'로 넘겨버려요"
>
> — 상시 · 막힌 이유: 모호한 첫 질문에 대한 되묻기·맥락 수집이 안 됨 · 원하는 것: **알프가 능동적으로 되물어 맥락을 확보한 뒤 처리하거나 정리해 이관**

> "소재·세탁·다림질 질문이 오면 상세페이지나 케어라벨을 매번 찾아 확인하고, 애매하면 MD에게 물어 반나절씩 늦어져요"
>
> — 상시 · 막힌 이유: 소재 정보가 상품마다 정리된 위치가 달라 신입은 어디서 찾을지도 모름 · 원하는 것: **알프가 상세페이지에서 소재·세탁·사이즈 정보를 바로 찾아 응답**

> "오배송 클레임은 물류·재고 시스템을 오가며 주문번호를 복사해 붙여 조회하고 회수를 따로 넣다가 다른 주문 회수를 잘못 잡은 적도 있어요"
>
> — 하루 몇 건 (사이즈 교환은 하루 수십 건) · 막힌 이유: 재고·회수 시스템이 상담 화면과 분리돼 정보를 수기로 옮겨야 함 · 원하는 것: **조회·회수 처리를 자동화해 화면 이동·복붙 제거**


## 2. 무엇부터 자동화하나 (우선순위)

반복·정형이면서 상담원 개입이 불필요한 것부터. 개별 확인이 필요한 유형은 후순위.

1. **배송조회** — 현재: 택배사 사이트 수기 조회 · 적합도 high
2. **재입고 안내** — 현재: 매크로 복붙(자연어 매칭 약함) · 적합도 high
3. **소재/세탁/사이즈 안내** — 현재: 상세페이지 수기 검색, MD 문의 · 적합도 high
4. **주문취소** — 현재: 어드민에서 상담사 취소 · 적합도 mid
5. **조건부 교환/반품 접수** — 현재: 조건 수기 확인 후 어드민 접수 · 적합도 mid
6. **회수/환불 처리** — 현재: 외주 WMS·PG 통해 상담사 처리 · 적합도 low

## 3. 성패를 가르는 연동 진단

**실제 처리(주문·예약 등)까지 자동화 가능 — 다만 백엔드 연동이 해결률 상한을 좌우.** Task별 연동 난이도가 곧 해결률 상한이다.

- **배송조회** — `workflow` · 시스템 택배사 조회(separate) · API yes · vendor · 공수 낮음(기성 함수)
- **재입고/소재 안내** — `no_integration` · 시스템 상세페이지·상품 DB(문서/RAG)(integrated) · API yes · inhouse · 공수 낮음(지식 정비 중심)
- **주문조회/취소/교환접수** — `system_task` · 시스템 자체 커머스 백엔드(내부 REST API)(integrated) · API yes · inhouse · 공수 약 2주(알프 전용 안전 엔드포인트 + 서버측 조건검증)
- **회수 처리** — `system_task` · 시스템 외주 WMS(separate) · API yes · vendor · 공수 높음(WMS 규격 대응 + 테스트 2~3주)
- **환불(금액 계산)** — `system_task` · 시스템 외부 PG + 쿠폰/적립금 로직(separate) · API yes · vendor · 공수 높음(부분환불·검증 복잡, 별도)

## 4. 알프에게 무엇을 준비시키나 (지식·공수)

- FAQ 추정 **50개**, 문서 교환·반품 정책 등 8건이 노션에 흩어져 있음 + 상품별 소재/케어 정보 산재
- 정비 포인트: FAQ가 단어형이라 자연어 매칭 약함 → 문장형 전환 필요, 소재 정보 위치 표준화 필요 · 예상 공수 FAQ 문장형 전환 + 도큐먼트화 하루~이틀
- 데모는 몇 분이지만 실운영 품질은 지식 정비 수준이 좌우한다.

## 5. 성공을 무엇으로 볼까 (지표)

- 목표: 프로모션 피크 문의 적체 해소(인력 증원 없이), 동일 문의 재인입률 하락, 응대 지연으로 인한 주문 이탈 방지, 성수기 CS 인건비 절감
- 성공 정의: 자동해결률 절대치는 내부 참고 지표일 뿐. 이사회 보고 기준은 재구매율·이탈 방지·인건비 효율
- 성과 지표는 **자동해결률 단독으로 잡지 않는다**(무리한 자동화는 CX를 해친다). 해결률 × 재인입률 × 응답시간 × 인력 절감 × CSAT를 묶어서 본다.

## 6. 상담팀은 어떻게 바뀌나

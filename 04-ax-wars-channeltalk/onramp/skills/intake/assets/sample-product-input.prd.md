# 고객 페인 + 제품 제안서 — 무브온 (가상 패션 이커머스)

> 본진 프로덕트팀 전달용. 근거: intake 음성 인터뷰(`output/transcript.jsonl`).

## 0. 고객 페인포인트 (실제 인용)
- "지난 시즌오프 프로모션 때 하루 2000건 넘게 들어와서, 5명이 밤까지 붙어도 답이 밀렸어요" — 빈도 대형 프로모션마다 (분기 1~2회), 미해결 원인: 교환·반품은 주문 상태랑 재고를 어드민에서 하나하나 확인해야 해서 알프한테 못 넘겼어요
- "재입고 문의는 하루에도 수십 번 똑같은 답을 복붙해요" — 빈도 상시, 미해결 원인: FAQ가 단어 위주라 알프가 잘 못 잡아냄

## Problem Statement
지난 시즌오프 프로모션 때 하루 2000건 넘게 들어와서, 5명이 밤까지 붙어도 답이 밀렸어요 — 반복·정형 문의가 피크에 폭증하는데 실제 처리가 사람에 묶여 있다.

## Solution
- 교환·반품 접수랑 주문 조회를 알프가 대신 처리
- 재입고 안내를 알프가 단독 처리

## User Stories
1. As a 고객사 CS 담당, I want 알프가 배송조회를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 재입고문의를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 주문취소를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
1. As a 고객사 CS 담당, I want 알프가 교환/반품 접수를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다

## Implementation Decisions
- 배송조회: tier `workflow`, 백엔드 택배사 조회, API yes — 파일·코드는 명시하지 않음
- 재입고문의: tier `no_integration`, 백엔드 없음(FAQ로 충분), API n/a — 파일·코드는 명시하지 않음
- 주문취소: tier `system_task`, 백엔드 자체 주문 어드민, API unknown — 파일·코드는 명시하지 않음
- 교환/반품 접수: tier `system_task`, 백엔드 자체 주문 어드민 + 외주 WMS, API unknown — 파일·코드는 명시하지 않음

## Testing Decisions
- 외부 동작(고객 요청 → 처리 결과)만 검증한다. 구현 세부는 테스트하지 않는다.
- 유사 선례: 기존 태스크 자동화(주문취소·교환) 케이스의 종단 시나리오.

## Out of Scope
- 이번 인터뷰에서 확인되지 않은 시스템·업무(아래 미해결 질문 참조).

## Further Notes
- 자체 주문 어드민이 외부 API를 제공하는지 (개발팀 확인)
- 외주 WMS 연동에 대응 개발이 얼마나 걸리는지
- 피크 프로모션 일정과 배포 완료 목표일 정합성

## 제품 갭 태그 분류 (누적 시 우선순위 신호)
- `[action_task]` × 1건: 교환·반품을 알프가 실제로 접수까지 해줬으면 좋겠어요
- `[knowledge_authoring]` × 1건: FAQ를 하나하나 문장으로 바꾸는 게 제일 일이에요
- `[voc_distribution]` × 1건: 반품 사유를 모아서 기획팀에 전달할 수 있으면 좋겠어요

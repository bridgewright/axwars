# 고객 페인 → 제품 제언 — 무브온 (가상 패션 이커머스)
> 본진 프로덕트팀 전달용 · 근거: cs_lead 인터뷰

## ⚡ 결론 먼저 — 제언

**교환·반품을 '답변'이 아니라 '실제 접수·처리'까지 해내는 액션 태스크가 최우선**

리더가 사람이 꼭 개입해야 하는 지점으로 교환·반품 접수를 꼽았고, 이는 해결률을 30%대에서 80%대로 끌어올리는 핵심이다. 지식 저작 자동화와 반품 사유의 기획팀 유통도 반복 신호다.

- **신호 강도(태그별 건수)**: 실제 처리(액션/태스크) 1건, 지식 저작 자동화 1건, 상담 데이터 타부서 유통 1건

## 고객이 실제로 겪는 문제 (현장 인용)

> "지난 시즌오프 프로모션 때 하루 2000건 넘게 들어와서, 5명이 밤까지 붙어도 답이 밀렸어요"
>
> — 대형 프로모션마다 (분기 1~2회), 막힌 이유: 교환·반품은 주문 상태랑 재고를 어드민에서 하나하나 확인해야 해서 알프한테 못 넘겼어요

> "재입고 문의는 하루에도 수십 번 똑같은 답을 복붙해요"
>
> — 상시, 막힌 이유: FAQ가 단어 위주라 알프가 잘 못 잡아냄


## Problem Statement
지난 시즌오프 프로모션 때 하루 2000건 넘게 들어와서, 5명이 밤까지 붙어도 답이 밀렸어요 — 반복·정형 문의가 특정 시점에 폭증하는데 실제 처리가 사람에 묶여 있다.

## Solution
- 교환·반품 접수랑 주문 조회를 알프가 대신 처리
- 재입고 안내를 알프가 단독 처리

## User Stories
- As a 고객사 CS 담당, I want 알프가 **배송조회**를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
- As a 고객사 CS 담당, I want 알프가 **재입고문의**를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
- As a 고객사 CS 담당, I want 알프가 **주문취소**를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다
- As a 고객사 CS 담당, I want 알프가 **교환/반품 접수**를 자동 처리, so that 반복 응대를 줄이고 피크에 대응한다

## Implementation Decisions
- 배송조회: `workflow` — 백엔드 택배사 조회, API yes, 개발 주체 vendor (파일·코드는 명시하지 않음)
- 재입고문의: `no_integration` — 백엔드 없음(FAQ로 충분), API n/a, 개발 주체 n/a (파일·코드는 명시하지 않음)
- 주문취소: `system_task` — 백엔드 자체 주문 어드민, API unknown, 개발 주체 inhouse (파일·코드는 명시하지 않음)
- 교환/반품 접수: `system_task` — 백엔드 자체 주문 어드민 + 외주 WMS, API unknown, 개발 주체 vendor (파일·코드는 명시하지 않음)

## Testing Decisions
- 외부 동작(고객 요청 → 처리 결과)만 검증한다. 구현 세부는 테스트하지 않는다.
- 유사 선례: 기존 태스크 자동화(주문·교환·구독취소 등)의 종단 시나리오.

## Out of Scope
- 이번 인터뷰에서 확인되지 않은 시스템·업무(아래 '결정 필요' 참조).

## Further Notes
- 자체 주문 어드민이 외부 API를 제공하는지 (개발팀 확인)
- 외주 WMS 연동에 대응 개발이 얼마나 걸리는지
- 피크 프로모션 일정과 배포 완료 목표일 정합성

## 제품 갭 — 무엇을, 왜 (태그별 우선순위)

### `[action_task]` 실제 처리(액션/태스크) — 1건
- 신호: 교환·반품을 답변만이 아니라 실제 접수·처리까지 원함
  > "교환·반품을 알프가 실제로 접수까지 해줬으면 좋겠어요"

### `[knowledge_authoring]` 지식 저작 자동화 — 1건
- 신호: FAQ 문장형 전환이 수작업이라 부담
  > "FAQ를 하나하나 문장으로 바꾸는 게 제일 일이에요"

### `[voc_distribution]` 상담 데이터 타부서 유통 — 1건
- 신호: 반품 사유 데이터를 상품기획팀에 넘기고 싶음
  > "반품 사유를 모아서 기획팀에 전달할 수 있으면 좋겠어요"

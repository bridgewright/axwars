## ⚡ 결론 먼저 — 권고

**배송조회·재입고부터 즉시 자동화하고, 교환·반품은 주문 어드민 API 확인 후 태스크로 확장하라**

문의의 절반이 배송조회·재입고 같은 반복·정형이라 즉시 효과가 크다. 반면 손이 가장 많이 가는 교환·반품은 실제 처리라서, 자체 주문 어드민과 외주 WMS 연동이 해결률의 상한을 결정한다.

- **준비도 진단**: yellow — 반복 문의는 즉시 도입 가능, 교환·반품 자동화는 연동 확인이 선행되어야 함
- **먼저 볼 리스크**: 자체 주문 어드민 API 유무 미확인; 외주 WMS 대응 개발 기간 미정; 피크 프로모션 일정과의 촉박함

## 1. 왜 지금인가 — 현장의 목소리

> "지난 시즌오프 프로모션 때 하루 2000건 넘게 들어와서, 5명이 밤까지 붙어도 답이 밀렸어요"
>
> — 대형 프로모션마다 (분기 1~2회) · 막힌 이유: 교환·반품은 주문 상태랑 재고를 어드민에서 하나하나 확인해야 해서 알프한테 못 넘겼어요 · 원하는 것: **교환·반품 접수랑 주문 조회를 알프가 대신 처리**

> "재입고 문의는 하루에도 수십 번 똑같은 답을 복붙해요"
>
> — 상시 · 막힌 이유: FAQ가 단어 위주라 알프가 잘 못 잡아냄 · 원하는 것: **재입고 안내를 알프가 단독 처리**


## 2. 무엇부터 자동화하나 (우선순위)

반복·정형이면서 상담원 개입이 불필요한 것부터. 개별 확인이 필요한 유형은 후순위.

1. **배송조회** — 현재: 택배사 사이트 수기 조회 · 적합도 high
2. **재입고문의** — 현재: 매크로 복붙 · 적합도 high
3. **주문취소** — 현재: 어드민에서 상담사가 취소 · 적합도 mid
4. **교환/반품 접수** — 현재: 어드민 확인 후 상담사 처리 · 적합도 mid

## 3. 성패를 가르는 연동 진단

**실제 처리(주문·예약 등)까지 자동화 가능 — 다만 백엔드 연동이 해결률 상한을 좌우하고, 일부 시스템은 API 유무가 아직 미확인.** Task별 연동 난이도가 곧 해결률 상한이다.

- **배송조회** — `workflow` · 시스템 택배사 조회(separate) · API yes · vendor · 공수 낮음(기성 함수)
- **재입고문의** — `no_integration` · 시스템 없음(FAQ로 충분)(n/a) · API n/a · n/a · 공수 없음
- **주문취소** — `system_task` · 시스템 자체 주문 어드민(integrated) · API unknown · inhouse · 공수 미정(개발팀 확인 필요)
- **교환/반품 접수** — `system_task` · 시스템 자체 주문 어드민 + 외주 WMS(separate) · API unknown · vendor · 공수 외주 대응 필요(기간 미정)

## 4. 알프에게 무엇을 준비시키나 (지식·공수)

- FAQ 추정 **50개**, 문서 교환·반품 정책 등 8건
- 정비 포인트: FAQ가 단어형 → 문장형 전환 필요 · 예상 공수 약 3시간 + 테스트
- 데모는 몇 분이지만 실운영 품질은 지식 정비 수준이 좌우한다.

## 5. 성공을 무엇으로 볼까 (지표)

- 목표: 프로모션 피크 문의 적체 해소, 재인입률 하락, 응답시간 단축
- 성공 정의: 자동해결률 절대치보다 재인입률·CSAT를 함께 본다
- 성과 지표는 **자동해결률 단독으로 잡지 않는다**(무리한 자동화는 CX를 해친다). 해결률 × 재인입률 × 응답시간 × 인력 절감 × CSAT를 묶어서 본다.

## 6. 상담팀은 어떻게 바뀌나

- 역할 전환: 단순 응대 → 상품정보 세팅·반품 사유 VoC 분석·품질 체크
- 변화관리 리스크: 낮음 (리더가 역할 전환에 우호적)
